# Формат ADR (MADR)

Архітектурно значущі рішення (фреймворк, БД, формат API, структура модулів, інструменти) фіксуються як ADR за
форматом **MADR 4.0.0** (<https://adr.github.io/madr/>).

- **Де лежать:** `docs/decisions/`
- **Назва файлу:** `NNNN-kebab-case-title.md` — чотири цифри без пропусків, латиниця (`0001-use-fastify.md`)
- **Статуси:** `proposed` → `accepted` / `rejected`; пізніше `deprecated` або `superseded by ADR-0007`
- Одна ADR — одне рішення. Прийнятий ADR не редагується: зміна рішення = нова ADR

## Мінімальний шаблон

```markdown
# {Коротка назва: розв'язана проблема + знайдене рішення}

## Context and Problem Statement

{2–3 речення: контекст і проблемне питання.}

## Considered Options

- {варіант 1}
- {варіант 2}

## Decision Outcome

Обрано "{варіант 1}", бо {обґрунтування}.

### Consequences

- Добре, бо {плюс}
- Погано, бо {мінус}
```

## Повний шаблон

```markdown
---
status: 'proposed'
date: YYYY-MM-DD
decision-makers: { хто ухвалив рішення }
consulted: { кого питали }
informed: { кого поінформували }
---

# {Коротка назва}

## Context and Problem Statement

{контекст і проблема}

## Decision Drivers

- {обмеження або рушій рішення}

## Considered Options

- {варіант}

## Decision Outcome

Обрано "{варіант}", бо {обґрунтування}.

### Consequences

- Добре, бо {плюс}
- Погано, бо {мінус}

### Confirmation

{як перевіримо, що рішення дотримано: тест, рев'ю, лінтер}

## Pros and Cons of the Options

### {варіант}

- Добре, бо {аргумент}
- Нейтрально, бо {аргумент}
- Погано, бо {аргумент}

## More Information

{посилання, коли переглянути рішення}
```

## Правила

- заголовок без нумерації, без жирного/курсиву;
- плейсхолдери — у фігурних дужках `{}`;
- `Decision Outcome` перед детальним `Pros and Cons`; граматика однакова для outcome і для варіантів;
- аргументи — «Добре / Погано / Нейтрально, бо …»;
- `Consulted` та `Informed` — за потреби (RACI), самі поля не обов'язкові;
- посилання на інші ADR — у тексті, напр. «див. ADR-0001».
