# Формат специфікації (spec.md)

Цей шаблон використовується для опису кожної ітерації (лабораторної роботи) перед початком її виконання. Оригінал зберігається у `standards/spec-format.md`.

**Обмеження обсягу:** приблизно **одна сторінка** — орієнтовно до ~6000 символів markdown (≈ 100 рядків разом
із таблицями). Усе, що не вміщається (ER-діаграми, детальні схеми, розрахунки), виносимо в окремі документи
в `docs/` і посилаємось на них.

## Context

- **Problem:** [Яку проблему вирішує ця фіча/лабораторна?]
- **Current behavior:** [Як система працює зараз, до внесення змін?]
- **Users or systems affected:** [Хто або що відчує ці зміни?]

## Goal

- **The smallest useful outcome:** [Мінімальний робочий результат, який вважатиметься успіхом для цього PR]

## Scope

- **In scope:** [Що конкретно ми робимо (напр., налаштування БД, написання CI)]
- **Allowed write paths:** [Які файли або директорії ми маємо право змінювати]
- **Read-only context:** [Що ми не чіпаємо, але використовуємо для розуміння]

## Technical Implementation (Адаптивний розділ)

> _Цей розділ змінюється залежно від завдання._

- **Розбиття та ER-моделі** (для роботи з БД).
- **Політики мерджу та етапи пайплайну** (для CI/CD).
- **Сценарії навантаження** (для пошуку боттлнеків).

## Non-goals

- **Explicitly excluded:** [Що ми свідомо НЕ робимо в цьому PR, щоб не ускладнювати його]
- **Dependencies or contracts that must not change:** [Що має залишитися незмінним]

- [ ] AC-3: [Критерій 3]

## Evidence

- **Automated tests:** [Які скрипти чи тести доведуть, що це працює]
- **Manual checks:** [Які команди треба виконати рев'юеру (напр., `make test`)]
- **Logs, screenshots, metrics:** [Що буде прикріплено до PR як доказ (скріни консолі, звіти профайлера)]
