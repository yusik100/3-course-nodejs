# Definition of Done (DoD)

Умова, за якої ітерація (лабораторна робота) вважається завершеною. Пункти з поміткою _(згодом)_ вмикаються,
коли в проєкті з'явиться відповідна інфраструктура.

## Код

- [ ] Реалізовано рівно те, що описано в `spec`; зміни не виходять за `Allowed write paths`.
- [ ] `make lint` — 0 помилок; попередження не накопичуємо.
- [ ] `make typecheck` — без помилок; немає `any` та `@ts-ignore` без пояснення.
- [ ] `make format-check` — файли відформатовані.
- [ ] `make build` — збірка проходить.
- [ ] Межі модулів не порушені (немає імпортів внутрішніх файлів іншого модуля).
- [ ] Помилкові кейси дають зрозумілу відповідь, без стектрейсів назовні.
- [ ] Немає `TODO`/`FIXME` без посилання на задачу.

## Перевірки та докази

- [ ] Кожен `AC-*` зі spec перевірено (тест, `curl` або ручний сценарій).
- [ ] Команди з розділу `Evidence` виконані, результат зафіксовано.
- [ ] `make lint`, `make typecheck`, `make build` прогнано після останньої правки.
- [ ] `npm run smoke` — зелений (`pass 1`, `fail 0`); _(згодом)_ повний набір тестів на бізнес-логіку.

## Репозиторій

- [ ] Коміт зроблено без `--no-verify`.
- [ ] У коміті немає `node_modules/`, `dist/`, `.env`, `.husky/_/`.
- [ ] Секретів у коді немає; `.env` — у `.gitignore`.
- [ ] Коміт(и) описують, що змінено і навіщо.
- [ ] README / spec / ADR оновлені, якщо змінилися команди, контракт або рішення.

## Чого DoD не вимагає

100% покриття тестами, ідеального дизайну, оптимізації без вимірів, виправлення всього, що помітили по дорозі
(для цього — окрема задача).
