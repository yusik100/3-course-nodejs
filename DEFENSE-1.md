DEFENSE — Завдання 1: Фундамент і структура застосунку

Що я реалізував (1–2 речення):

Створено базовий каркас проєкту (Fastify \+ TypeScript) та закладено інженерні стандарти (spec, ADR, DoD, лінтери, Git-хуки) на весь курс. Спроєктовано архітектуру модульного моноліту (модулі Users та Tickets), розроблено ER-модель для бази даних SQLite та реалізовано базовий smoke-тест.

Топ-3, де я «зрізав кути» / знайшов і виправив (проти spec):

• Невідповідність версії TypeScript: Лінт-плагін typescript-eslint вимагав версію TS \<6.1.0, але у package.json стояла каретка ^6.0.3, що створювало ризик поломки при оновленні до версії 7.x. Виправлено жорстким закріпленням версії "typescript": "\~6.0.3".  
• Конфлікт типів та рантайму Node.js: Залежність @types/node мала версію 26.6.3 (або 24.19.0), тоді як в engines було вказано \>=20.6.0, що дозволяло компілювати код для непідтримуваного API. Виправлено синхронізацією: встановлено engines.node: "\>=24.13.0" та відповідні типи ^24.0.0.  
• «Примарна» структура папок (заглушки): За специфікацією структуру було лише спроєктовано, але Git ігнорує порожні папки. Щоб архітектура (src/config/, src/modules/...) збереглася в репозиторії, було згенеровано 19 файлів-заглушок (наприклад, export {}; або SQL-коментарі).

Ключове рішення — які альтернативи зважив і чому обрав цю (ADR):

Вибір БД (ADR-0001): Розглядалися better-sqlite3, PostgreSQL та вбудований node:sqlite. Обрано node:sqlite, оскільки цей драйвер працює «з коробки» у Node.js 24+, не вимагає компіляції native-модулів на Windows, не збільшує кількість сторонніх залежностей та надає зручний синхронний API (DatabaseSync) для простих транзакцій.
