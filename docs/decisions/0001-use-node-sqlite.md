# Вбудований node:sqlite як драйвер бази даних

## Context and Problem Statement

Проєкт зберігатиме користувачів, задачі та коментарі в реляційній базі даних, тому потрібен драйвер — БД і спосіб
доступу до неї з Node.js. Обраний варіант має працювати на Windows без native-збірки, не додавати зайвих залежностей
(у `dependencies` поки що лише Fastify) і давати прості транзакції для ключових сценаріїв зі spec-01.

## Decision Drivers

- Мінімум залежностей: у проєкті поки що один пакет у `dependencies`.
- Робота «з коробки» на Windows: без компіляції native-модуля та без prebuild-бінарників.
- Синхронний API — «один сценарій = одна транзакція» реалізується тривіально.
- Сумісність типів і рантайму: `@types/node` має описувати той самий Node, що й виконує код.
- Мінімальна версія Node (`engines`) — має бути реальною, а не декларацією.

## Considered Options

- `node:sqlite` — вбудований модуль Node.js (`DatabaseSync`)
- `better-sqlite3` — стороння native-бібліотека
- PostgreSQL із драйвером `pg` — окремий сервер БД

## Decision Outcome

Обрано "`node:sqlite`", бо модуль уже вбудований у Node.js 24 (LTS), не потребує native-збірки, дає синхронний
`DatabaseSync` для тривіальних транзакцій і не збільшує `dependencies`.

### Consequences

- Добре, бо нуль нових залежностей: `npm ci` на чистому клоні нічого не збирає.
- Добре, бо синхронний API (`exec`, `prepare`, `get/all/run`) робить транзакції звичайним послідовним кодом.
- Добре, бо типи вже в `@types/node` — окремо `@types/*` для драйвера не потрібні.
- Погано, бо модуль має статус «Stability 1.1 — active development»: API може змінюватися між мажорними версіями
  Node, а при старті з'являється `ExperimentalWarning: SQLite is an experimental feature...` (вирішили лишати
  його видимим, щоб не приховувати стан речей).
- Погано, бо мінімальна версія Node зростає до 24.13.0: `engines` і `@types/node` тепер прив'язані до однієї
  лінії та оновлюються разом.
- Погано, бо немає вбудованих зручностей вищого рівня (міграції, хелпери транзакцій) — їх доведеться писати
  в `src/db/` самостійно.

### Confirmation

- `engines.node` = `>=24.13.0`, `@types/node` = `^24` — синхронізовано з рантаймом (перевірка: `npm ls @types/node`).
- Швидка перевірка середовища: `node -p "typeof require('node:sqlite').DatabaseSync"` → `function`.
- Код використовує лише базовий API драйвера: `DatabaseSync`, `exec`, `prepare`, `get`, `all`, `run`.
- `npm run smoke` і `npm run typecheck` — зелені після будь-якої зміни залежностей.

## Pros and Cons of the Options

### node:sqlite — вбудований модуль Node.js

- Добре, бо без залежностей і native-збірки — працює на будь-якій збірці Node 24.
- Добре, бо документація й типи постачаються разом із Node.
- Нейтрально, бо стабільність лише 1.1 — попередження про експериментальність очікувані.
- Погано, бо складні сценарії (міграції, пулинг, async-обв'язка) доведеться будувати вручну.

### better-sqlite3

- Добре, бо зріла бібліотека з великим досвідом експлуатації.
- Добре, бо багато хелперів і готові рецепти транзакцій.
- Погано, бо native-модуль: на Windows встановлення залежить від наявності prebuild під конкретну версію Node.
- Погано, бо ще одна залежність із native-компонентом у проєкті, де їх поки що немає.

### PostgreSQL із pg

- Добре, бо окремий сервер — чиста ізоляція даних і реальний SQL-діалект.
- Погано, бо для розробки й здачі лаби потрібен запущений сервер — додатковий крок «як розпочати».
- Погано, бо міграція ER-діаграми на інший діалект і більше залежностей усередині.
